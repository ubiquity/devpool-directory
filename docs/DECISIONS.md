# Decisions

## 2026-10-18: Directory sync state and recovery

Persisted issue history and mirror mappings are durable state. Incremental omissions must preserve them, and only a genuine missing artifact may load as empty state. Large files use authenticated raw retrieval rather than the Contents API's inline payload. Fully paginated source fetches and existing mirror bodies recover lost identities before any creation.

A failed fetch, invalid artifact, reconciliation failure, or missing shard output fails the sync. Aggregate publication depends on every shard succeeding; a failed run must not publish a successful watermark. Matrix Sync and Backfill Historical share the directory-sync-__STORAGE__ concurrency group with cancel-in-progress disabled, serializing writes to the same artifact branch across code refs.

The recovery audit found unique human implementation and payout comments on directory issues #5931 and #5969. Preserve the existing duplicate pairs #5076/#5931 and #5839/#5969 unchanged under the protection of user-owned state. Deleting these discussion-bearing mirrors is outside this sync repair's scope. Recovery acceptance compares the unique public eligible source URL set with the open mirror URL set, requires no new duplicates, and retains these two baseline pairs.

The duplicate cleanup job remains available only through its existing manual dispatch. Automatic cleanup stays on hold to protect these discussions. Any future cleanup of the two baseline pairs requires an explicit owner decision on archival and deletion. This is a scoped recovery exception; the repository's existing duplicate policy remains in force for other work.

Matrix Sync sets the existing TWEET_ON_CREATE and DELETE_TWEET_ON_COMPLETE controls to false when full_resync is true, so full recovery does not replay Twitter lifecycle actions from historical issues. Manual incremental runs with full_resync=false and scheduled runs with no input automatically retain the original true behavior. This rule requires no separate restoration release and leaves the manual-only duplicate cleanup hold in force.

The sync regressions use node:test through the existing tsx dependency. The test command names the current sync regression files explicitly because the archived Jest/MSW tests require dependencies and source modules absent from this version. No additional test framework is introduced.

Every exact recovery response requires a current repository visibility read with private === false before its metadata can replace cached source state or drive mirror writes, including unchanged source URLs. Private, unknown, or failed visibility checks fail before publication. Verified responses replace current labels, title, body, assignees, canonical identity, state, and timestamps before reconciliation and statistics. Completed rewards use the current price; removed prices follow the existing unpriced policy, and cancelled sources remain excluded from rewards and opportunity artifacts. Node identity and configured redirect scope checks remain required; fresh ingestion still supplies its existing public discovery contract when an exact read is unnecessary.

Shards perform no Twitter lifecycle actions. Aggregate first commits source artifacts and a durable twitter-pending.json outbox; only fresh shard issues may introduce new creation candidates. Before posting, it persists the authenticated account, second-aligned attempt time, and original source URL. Explicitly rejected posts remain retryable; transport failures, server errors, duplicate-content responses, missing receipt IDs, and failed receipt writes retain an unresolved attempt that prohibits reposting. Each successful response is persisted before another operation.

Unresolved Twitter attempts survive source closure, omission, and lost eligibility. Recovery scans at most 1,000 authenticated account timeline entries in the attempt-to-lookup time window, requires terminal pagination without partial errors, and accepts exactly one matching account, timestamp, and expanded original source URL. It persists that recovered ID before completion cleanup, including completion verified by an exact source read with an empty shard delta. Missing, ambiguous, incomplete, or unavailable evidence fails closed with the attempt retained; a marker committed before a crash that sent no post can therefore remain blocked. Full-resync suppression disables both lifecycle actions and all Twitter API calls while preserving attempts. This avoids unattended reposts without claiming transactional Twitter idempotence.

Twitter cleanup intent is recomputed from current verified source state. Reopening with a price clears obsolete completion cleanup and preserves an existing announcement receipt. An unresolved creation attempt survives that reopening until recovery establishes its original ID, without deleting or reposting the active announcement. Missing, unpriced, and cancelled sources retain required cleanup intent.

When the shards directory is absent, historical backfill aggregation discovers its current include/exclude repository scope from configuration and preserves existing sync watermarks and published pull requests. A non-array saved pull request artifact fails before reconciliation or publication. Discovery does not mark cached issues as freshly fetched, so exact redirects still require stable node identity and verified public visibility. An existing empty or incomplete shard tree fails rather than using this fallback; Matrix Sync keeps its successful shard-derived scope and merged shard pull requests. Backfill explicitly disables both Twitter lifecycle controls and supplies the existing read credential and write-target guard.

Historical backfill verifies each discovered repository through repos.get before fetching its history. Only private === false permits ingestion; explicit private repositories are skipped, and failed or unknown visibility fails before publication. The write-target guard must match the intended repository before the history seed or aggregate writes. The accepted baseline contains no private published records, so this guard adds no cleanup of existing records.
